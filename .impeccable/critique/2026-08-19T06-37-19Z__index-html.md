## Priority Issues

**[P1] Zero-gap crowding between logo and hamburger at 320px — [pre-existing, NOT caused by this PR — corrected finding]**
- **What**: At 320px, `.logo`'s right edge and `.nav-hamburger`'s left edge sit at the identical x-coordinate (233px), a measured 0px gap.
- **Note on process**: Assessment A's index.html run initially labeled this **[PR-caused]**, reasoning from arithmetic (44→48px growth "ate" an assumed pre-existing cushion) without directly testing causation. This conflicts with Assessment A's testimonials.html run, which tested causation directly (reverted `.nav-hamburger` to 44×44px via injected CSS) and found the gap stayed 0px, concluding pre-existing. The orchestrator resolved the conflict by re-running the same override test directly on index.html at 320px: with the hamburger forced back to 44×44px, `.logo` right edge shifts from 233 to 237 and `.nav-hamburger` left edge shifts identically from 233 to 237 — **gap remains 0px in both configurations**. The cause is `.nav-inner`'s `justify-content: space-between` with no `gap` and an unconstrained `.logo` box, which reflows to fill available space up to whatever sits next to it regardless of that element's width. This PR's 44→48px hamburger change is confirmed **not** the cause, on both pages.
- **Why it matters**: Reads as a layout accident rather than a deliberate minimal header at the narrowest supported width; a small polish signal that can erode first-visit trust.
- **Fix**: Add `gap: 8px` to `.nav-inner`, or a minimum `margin-left` on `.nav-hamburger`. Because index.html duplicates `.nav-inner`/`.logo`/`.nav-hamburger` in its own inline `<style>` block (it doesn't load shared.css), any fix needs to land in both `shared.css` (for the 163 partial-driven pages) and `index.html`'s inline styles.
- **Suggested command**: `/impeccable polish` (small, mechanical, high-confidence CSS fix, out of scope for this PR).
- **File:line**: `shared.css:35,193`; `index.html:65,191` (duplicated inline copy).

**[P2] Homepage's 70px nav height is a silent, undocumented-in-shared-CSS one-off — [pre-existing, out of this PR's scope]**
- **What**: 163 of 164 pages run a 52px `.nav-inner` from shared.css via the partial-injection pipeline; the homepage alone runs its own self-contained inline stylesheet with a 70px nav height, confirmed identical between scroll-top and scrolled states (no separate transparent/solid nav states exist).
- **Why it matters**: Not a visible defect today, but it's a maintenance trap: this PR's site-wide rollout worked here because the phone-hide/hamburger-size rules are height-agnostic, but any future nav change that assumes a single shared source of truth will silently miss the homepage's duplicated copy, the same pattern that already required duplicating this PR's fix into `index.html:410-416` separately from `shared.css`.
- **Fix**: Not for this PR. Track separately: consider migrating the homepage off its self-contained inline stylesheet.
- **Suggested command**: `/impeccable audit` (site-wide structural finding).
- **File:line**: `index.html:65` vs `shared.css:35`.
